This report documents the integration of ISP services into an enterprise network environment. The project covers dual-WAN link configuration, routing between the internal network and external ISP infrastructure, SLA definitions, and the documentation standards used in professional network engineering engagements.

Scope & Objectives

The project was scoped around integrating a dual-ISP connection into an existing enterprise network. Key objectives included:

  • Configure and verify WAN interface addressing for primary and secondary ISP links
  • Establish default routing with floating static routes for automatic failover
  • Document SLA requirements for uptime, latency, and bandwidth
  • Verify end-to-end reachability from internal hosts to simulated internet destinations
  • Produce a professional-grade configuration report suitable for enterprise handover

WAN Link Configuration

Two separate WAN links were configured — a primary link with administrative distance 1 and a floating secondary link with administrative distance 10. This ensures the secondary path only becomes active when the primary fails, without manual intervention.

Routing Design

Default routes were configured at the enterprise router level with floating static route logic. OSPF was used internally to distribute the default route to all LAN-connected devices via default-information originate.

! Primary default route
ip route 0.0.0.0 0.0.0.0 8.8.8.2

! Floating secondary route (activates if primary fails)
ip route 0.0.0.0 0.0.0.0 8.8.8.6 10

! Distribute default route to OSPF domain
router ospf 1
 default-information originate

SLA Documentation

Service Level Agreement parameters were defined as part of the integration handover documentation. These define the expected performance thresholds the ISP must meet and the failover behaviour if those thresholds are not met.

Connectivity Verification

End-to-end reachability was verified from internal VLAN hosts to the simulated internet address (ISP loopback 9.9.9.9). Failover was tested by disabling the primary WAN interface and confirming traffic routed through the secondary path.

Result: Full connectivity confirmed from all VLAN segments to the ISP loopback address. Failover to the secondary WAN link occurred within the 5-second SLA target, with automatic restoration when the primary was re-enabled.

Key Learnings

  • Administrative distance is the simplest way to implement WAN failover without complex routing protocols
  • OSPF redistribution of the default route ensures no manual configuration is needed on internal routers
  • SLA documentation is as important as the technical configuration in enterprise environments
  • Failover testing must be performed before go-live to validate that the secondary path actually activates correctly
