Network Design

A complete multi-site enterprise network built in Cisco Packet Tracer — VLAN segmentation, OSPF dynamic routing, DHCP automation, and extended ACL enforcement between Sydney and Melbourne.

Project Overview

This project demonstrates a complete multi-site enterprise network build using Cisco Packet Tracer. Starting from a single-site layout, the network evolved into a fully routed, dual-site design featuring VLAN segmentation, dynamic routing via OSPF, automated IP addressing through DHCP, and traffic policy enforcement using extended ACLs.

Network Topology

Two sites connected over a routed GigabitEthernet point-to-point link (10.0.0.0/30). Each site has a Cisco 2911 router performing inter-VLAN routing and DHCP services, and a Cisco 2960 switch providing VLAN access ports and 802.1Q trunk connectivity.

VLAN Segmentation & Trunking

Each site uses two VLANs to separate traffic by department. VLAN 10 (Sales) carries traffic from PC1 on Fa0/2, while VLAN 20 (IT) carries traffic from PC2 on Fa0/3. FastEthernet0/1 is configured as an 802.1Q trunk on both switches toward the router.

Router-on-a-Stick Inter-VLAN Routing

Both routers use the router-on-a-stick technique — logical subinterfaces on GigabitEthernet0/0 with 802.1Q encapsulation. Each subinterface acts as the Layer 3 default gateway for its VLAN.

DHCP Configuration

Each router serves as a DHCP server for its local VLANs. Four pools were created — two per site — covering all four VLAN subnets. All pools use Google DNS (8.8.8.8). Successful leases were confirmed by checking binding tables and PC IP configurations.

OSPF Dynamic Routing

Static routes were replaced with OSPF process 1 in area 0 on both routers. After OSPF was enabled and the transit link was advertised, a full adjacency formed. LAN-facing subinterfaces are set as passive to prevent unnecessary OSPF hellos on end-device segments.

Extended ACL Traffic Policy

An extended ACL was applied to deny all IP traffic from Sydney VLAN 20 (192.168.20.0/24) destined for Melbourne VLAN 10 (192.168.30.0/24). All other traffic is permitted. Applied inbound on GigabitEthernet0/0.20 on the Sydney router.

access-list 100 deny ip 192.168.20.0 0.0.0.255 192.168.30.0 0.0.0.255
access-list 100 permit ip any any
interface GigabitEthernet0/0.20
 ip access-group 100 in

Connectivity Verification

End-to-end connectivity was validated using ping tests between PCs across both sites. The first packet typically shows one timeout due to ARP resolution, followed by 0% loss on repeat tests.

Result: Sydney VLAN 20 traffic is correctly blocked from reaching Melbourne VLAN 10 by the extended ACL, while all other inter-site traffic continues to flow via OSPF-learned routes — confirming the policy works as designed.
